# 工作流知识库定时同步

定时任务使用 `knowledge.meta.workflow_sync_input` 重跑当前工作流。首次开启前，需要手动运行一次
Web 或远程工具数据源。本地上传不能定时重新读取；已开启远程同步时，手动上传本地文件不会覆盖
已保存的远程运行输入。

## 文档来源

来源信息从数据源传到内容提取、分段和知识库写入，保存在 `document.meta` 中，并由现有文档查询接口返回：

- `source_type`：`web`、`local` 或 `tool`。工具可以显式提供 `lark` 等来源类型。
- `source_node_id`：数据源节点 ID；工具来源还有 `source_tool_id`、`source_tool_name`。
- `source_scope`：节点、节点配置和选定数据源输入的指纹，隔离不同站点、工具或选定文件夹。
  这里只保存指纹，不把数据源的访问凭据复制到文档。
- `source_url`：Web 的实际页面 URL；工具提供 URL 时保留原值。本地文件名不会写入此字段。
- `token`、`source_id`、`source_key`：工具提供的远程文档标识。
- `source_document_type`：工具提供的远程文档类型。
- `source_file_id`：原始上传或下载文件 ID。
- `workflow_action_id`：产出文档的执行 ID；定时产出还带有 `workflow_sync_log_id`，用于本次任务的精确清理。

飞书等下载工具的 `get_download_file_list` 返回项、`download` 返回值或其中的 `meta` 应提供远程
文档 `token`（也支持 `document_token`、`file_token`）、`source_key`、`source_id` 或 URL。
下载节点只提取这些来源字段和文档类型，不保存 `file_bytes`、访问令牌、应用密钥或其他下载参数。
没有稳定远程标识的文档仍可手动导入，但定时写入会明确报错，避免根据文档名错误匹配。

## 同步范围和失败处理

- 增量同步以来源范围和稳定文档标识匹配，保留旧文档 ID 并按已有分段同步规则处理变更。
  成功输出代表该来源的完整快照，包括空快照；只删除同一来源范围内不再输出的旧文档。
- 替换同步匹配同一来源的旧文档并覆盖内容，保留未匹配的旧文档。
- 整体同步成功后只替换同一来源范围内的旧文档。
- 工作流失败或取消时，只清理该同步执行产出的文档；其他执行、来源和本地上传不受影响。
- 单文档合并使用独立事务；合并失败保留旧数据并清理临时输出，阻止本轮清理未匹配旧文档。
- 重复的远程文档标识会导致同步失败，避免静默合并到错误文档。

历史 V2/V3 文档缺少 `source_scope` 时，不会自动按文档名认领或删除。它们会与首次带来源的新输出
并存；应在核对后手动整理历史重复文档。无需数据库迁移。
